1. Platform Overview

DockBound is a cruise intelligence platform serving two distinct audiences.

Consumer side — Cruise travelers who purchase DOCKGuides for their itinerary. A DOCKGuide is a full port-by-port guide covering every stop on a specific cruise: transport, food, safety, budget, and what to know before you dock. Individual port content within a DOCKGuide is called a port guide.

Professional side — Travel advisors and agencies who use DockBound's live intelligence dashboard to monitor their entire book of cruise business, powered by Travefy trip data and DockBound's proprietary DockScore system.

Landing pages — The root / route renders the Compass Landing page, a full-featured marketing hub built from shared landing components (LandingNav, LandingFooter). Dedicated audience-specific landing pages are live at /for-advisors (ForAdvisorsPage), /for-agencies (ForAgenciesPage), and /for-travefy (ForTravefyPage) — each with full content for their respective audiences, replacing the previous ComingSoonPage placeholders. The original consumer landing is accessible at /for-travelers. A public transparency page at /information-standards describes DockBound's data sources, content methodology, and quality practices for advisors, travelers, and partners evaluating the platform.

DockScore: A proprietary port accessibility and congestion rating (0–10, lower = better). A static baseline reflects normal conditions; a dynamic score adjusts for live signals. A port is flagged "at risk" when dynamic exceeds static by ≥ 0.5.
DOCKGuide vs. port guide: A DOCKGuide is the product a traveler purchases — it covers all ports on their itinerary. A port guide is the content for one specific port. Port guides are the building blocks of a DOCKGuide and are also maintained individually by the admin team.

3. User Journeys

Journey 1 — Traveler: Self-Serve Paid DOCKGuide

A cruise passenger discovers DockBound, previews their itinerary, and purchases a full DOCKGuide for their cruise.

  1. Discover — Arrives at Compass Landing (/) or Traveler Landing (/for-travelers)
  2. Browse — Searches for their cruise at /micro-selection, filtering by cruise line, ship, sail date, or region
  3. Preview — Views port-by-port itinerary preview at /preview with sample port guide content and DockScore teaser
  4. Authenticate — Signs up or logs in at /auth; if unauthenticated at checkout, session stores the cruise and redirects back post-auth
  5. Purchase — Completes Stripe checkout at /payment-checkout
  6. Confirm — Sees payment success at /payment-success
  7. Access — Full DOCKGuide on dashboard (/dashboard): all port guides, live weather, travel alerts, currency, tours, and DockScore
Functions: Search for cruise · Preview itinerary · Sign up / Log in · Purchase DOCKGuide · View DOCKGuide · Read port guide · View DockScore · View DOCK diagnostics · View port weather · View travel alerts · Convert currency · Browse & book tours · Print cruise guide · View upcoming cruises · View itinerary change alerts

Journey 2 — Traveler: Freemium Access

A traveler receives free or partial DOCKGuide access — via advisor referral, promotional access, or sign-up without purchase — and sees locked premium sections with an upgrade prompt.

  1. Arrive — Comes via advisor referral link or direct sign-up
  2. Authenticate — Signs up or logs in at /auth
  3. Access — Dashboard shows freemium content; locked sections display an upgrade prompt
  4. Upgrade — Can purchase full access from the upgrade prompt or at /upgrade/:orderId
Functions: Sign up / Log in · View freemium DOCKGuide (gated sections) · View locked section upgrade prompts · Upgrade to full paid access

Journey 3 — Advisor: Joins Solo, Manual Roster (No Travefy)

A travel agent signs up independently as an independentAdvisor, selects a subscription plan, builds a client roster manually, and uses the intelligence dashboard to monitor their book of business.

  1. Sign up — Creates an account at /auth?mode=signup&advisor=true; registerAdvisorRole CF sets role to agent with advisorType: independentAdvisor
  2. Onboarding — First dashboard visit shows the onboarding flow; advisor selects a plan and completes Stripe checkout with a 60-day trial period (trial_period_days: 60); card is required at signup but billing starts after 60 days
  3. Subscribe — Inline plan picker appears on the dashboard for trial users without a Stripe customer record; advisor selects a plan (Basic $199/mo, Professional $699/mo, or Engage $1,499/mo — same as Travefy Advisor tiers) and completes Stripe checkout
  4. Build roster — Adds travelers one at a time or bulk-imports via CSV; can also add a client directly from search results via the "Add Client" button on cruise cards
  5. Monitor — Uses the Sailings tab (Itinerary Timeline, Who's Sailing, Act Now, Intelligence) and Port Tools tab (Congestion Calendar, Port Guide & DOCK)
  6. Customize — Configures which guide sections clients see and in what order
  7. Deliver — Looks up port guides and DockScores for specific clients
Functions: Sign up / Log in · Subscribe to tier · Add traveler manually · Import travelers via CSV · Add client from search results · Archive / unarchive traveler · Add cruise to roster entry · View team roster · View archived travelers · Open traveler communication thread · Send in-app message · Log contact · Send SMS to traveler · View Itinerary Timeline · View Act Now queue · View Today's Ports · View Next 3 Days · View At-Risk Itineraries · View Who's Sailing timeline · View port congestion calendar · Look up port guide · View Port Day at a Glance · View DockScore · View DOCK diagnostics · Customize guide settings · View port utilization

Journey 4 — Advisor: Joins Solo, Links Travefy

An advisor links their Travefy account, syncing cruise trips automatically and enriching them with DockBound intelligence.

  1. Sign up & subscribe — Same as Journey 3, steps 1–2
  2. Connect Travefy — In the Settings tab (Travefy Sync section), authenticates and links account; AccessToken stored in Firestore
  3. Sync trips — Clicks "Sync Now"; trips pulled from Travefy and stored in agents/{uid}/trips
  4. Auto-sync — Nightly Cloud Function re-syncs all trips at 2am ET
  5. View enriched trips — DockScore and port guide data overlaid on each synced trip
  6. Enrich back — Writes DockBound TripEvents back to Travefy port days; registry stored in travefyEnrichments
  7. Monitor — All intelligence views draw from synced Travefy trip data
Functions: All functions from Journey 3 · Connect Travefy account · Sync Travefy trips manually · View Travefy trip list · Enrich Travefy trip · View enrichment records · Auto nightly trip sync

Journey 5 — Agency Host: Joins With Travefy

An agency admin provisions a DockBound agency, imports advisors, and oversees intelligence across all agents who connect Travefy.

  1. Sign up — Account provisioned with role agencyhost
  2. Create agency — Sets agency name, website, phone at /agency-hub; a corresponding org node is created in the Node system and nodeId is written to both the agency doc and the owner user doc
  3. Import agents — Uploads CSV of advisor roster at /agency-hub/import; each activated advisor gets a user node created under the agency's org node
  4. Invite agents — System auto-sends email invitations to each advisor
  5. Agents onboard — Each advisor follows Journey 4 to connect their own Travefy account
  6. Monitor — Agency Hub dashboard auto-detects advisor issues (inactive 14+ days, missing Travefy auth) and surfaces them as Attention Items; host reviews, marks viewed, or dismisses each item inline
  7. Reports & Roster — Reviews agent activity and referral analytics at /agency-hub/reports; manages agent status at /agency-hub/roster
Functions: Sign up / Log in · Create agency profile · View agency overview (attention-first dashboard) · View and manage attention items · Copy agency referral code · Import agent roster via CSV · View agent roster · Suspend / activate agents · View agency reports · (Advisors individually connect Travefy per Journey 4)

Journey 6 — Agency Host: Joins Without Travefy

An agency uses DockBound entirely without Travefy — advisors build rosters manually and the agency host monitors advisor activity and referral reports.

  1. Sign up & create agency — Same as Journey 5, steps 1–2
  2. Import & invite agents — CSV import + invite emails
  3. Agents build rosters manually — Each advisor follows Journey 3
  4. Monitor — Agency host reviews agent activity and referral reports
Functions: Same as Journey 5 excluding all Travefy-specific functions

Journey 7 — Advisor: Invited by Agency Host

An advisor receives an invite email from their host agency and joins DockBound as part of that agency's team.

  1. Receive invite — Gets email from the sendRosterInviteEmail Cloud Function
  2. Click link — Directed to sign-up with agency pre-linked via referral code or invite token
  3. Sign up — Creates account; linkAgentRoster Cloud Function associates them with the agency roster
  4. Activate — Roster entry status changes invited → active
  5. Use platform — Advisor proceeds with Journey 3 (manual) or Journey 4 (Travefy)
Functions: Sign up via invite link · Auto-link to agency roster · View advisor dashboard · All advisor functions from Journey 3 or 4

Journey 8 — Traveler: Referred by an Advisor

An advisor shares a referral link; the traveler signs up through it and their account is attributed to that advisor.

  1. Advisor shares link — Distributes unique referral link to a client
  2. Traveler clicks — Lands on DockBound with referral tracked in session
  3. Traveler signs up — agencyOnReferralSignup Cloud Function records attribution
  4. Traveler accesses guide — Receives freemium or paid access per the advisor's setup
  5. Advisor gets credit — Referral counted in agency reports
Functions: (Advisor) Share referral link · (Traveler) Sign up via referral · (Traveler) Access DOCKGuide · (System) Record referral attribution

Journey 9 — Advisor: Delivers DOCKGuide to Traveler Roadmap

An advisor proactively pushes a client's port guide to them for a port arriving today or tomorrow.

  1. Identify — Sees in "Who's Sailing" that a client arrives at port tomorrow
  2. Select — Chooses the client and specific port day
  3. Send — One-click delivery pushes DOCKGuide via email or in-app notification
  4. Traveler receives — Gets the port guide link before they even think to look
Functions: View Who's Sailing timeline · Send DOCKGuide to traveler (roadmap) · View delivery history (roadmap)

Journey 10 — Traveler: Day-of Port Experience

A traveler is arriving at port today and uses DockBound on their phone — potentially with limited ship Wi-Fi.

  1. Open app — Accesses /dashboard from mobile; today's port highlighted
  2. Read guide — Full port guide: snapshot, transport, safety contacts, food, budget
  3. Check alerts — Views any active travel advisory for the destination country
  4. Convert currency — Quick lookup of local exchange rate
  5. Book tour — Browses and books Viator tours for the port
  6. Check DockScore — Sees current congestion/accessibility rating
Functions: View today's port day · Read full port guide · View travel alerts · Convert currency · Browse & book Viator tours · View DockScore · Offline/cached port guide access

Journey 11 — Advisor: Self-Serve Free Trial (Travefy or Independent)

An independent travel advisor signs up for a 60-day free trial — either via the Travefy Advisor path (advisorType: travefyadvisor) or the independent advisor path (advisorType: independentAdvisor). Both use the same TRAVEFY_TIERS pricing and the same inline plan picker for conversion. The trial mechanics differ by path.

  1. Sign up — Creates account at /auth?mode=signup&advisor=true; role set to agent with the appropriate advisorType
  2. Trial starts — Account provisioned with plan.status: trialing and a trialEndsAt timestamp 60 days out. Travefy Advisor path: no Stripe payment required at signup — trial is held locally. Independent Advisor path: Stripe checkout with trial_period_days: 60 is required at onboarding; a credit card is collected but billing does not start until day 61
  3. Connect Travefy — (Travefy Advisor path only) Authenticates and links Travefy account; AccessToken stored in Firestore
  4. Access paid features — All advisor tabs and intelligence tools are available for the trial duration
  5. Trial nears end — Dashboard shows trial end date countdown; a "Subscribe" button appears in the plan banner
  6. Subscribe — Inline plan picker expands on the dashboard; advisor selects Basic $199/mo, Professional $699/mo, or Engage $1,499/mo; completes Stripe checkout; plan.status transitions to active. Applies to both travefyadvisor and independentAdvisor types
Functions: Sign up / Log in · Connect Travefy account (Travefy path) · Sync Travefy trips (Travefy path) · View Itinerary Timeline · View Act Now queue · View Cruise Change Feed · View Port Activity · Configure Alert Settings · View Who's Sailing timeline · Enrich Travefy trip (Travefy path) · Subscribe to tier (at trial end)

At-a-glance signal for how challenging a port is expected to be — green (low) to red (high).

Traveler, within their DOCKGuide dashboard.

Traveler, within their DOCKGuide dashboard.

Traveler is informed of any active safety, entry, or health advisories before arriving in that country.

5. Advisor Functions

Sign Up / Log In
What
Creates a new advisor account or authenticates an existing one.
Who
Travel agent, at /auth.
Result
Account with role agent established; advisor directed to the agent dashboard.
Subscribe to Tier
What
Initiates a Stripe subscription checkout for the advisor's chosen plan — 25, 100, 300, or 750 traveler slots (slot-based plans) or Basic $199/mo / Professional $699/mo / Engage $1,499/mo (Travefy Advisor and Independent Advisor plans, both use TRAVEFY_TIERS) — during first-time onboarding or trial-to-paid conversion. For trial advisors (travefyadvisor or independentAdvisor), an inline plan picker expands on the dashboard when they click "Subscribe" or "Change Plan".
Who
Advisor, during the onboarding flow on the agent dashboard or when converting from a trial; for slot-based plan advisors, during initial setup; for trial advisors, from the plan banner "Subscribe" button.
Result
Subscription active; roster slot capacity set; recurring billing established in Stripe.
Manage Billing
What
Opens the Stripe Billing Portal for the advisor to manage their subscription — view invoices, update payment method, or cancel. Requires an existing Stripe customer record on the agent's Firestore document (plan.stripeCustomerId). Implemented via the stripeCreatePortalSession Cloud Function.
Who
Advisor with an active Stripe subscription, from the agent dashboard billing section.
Result
Advisor redirected to the Stripe-hosted Billing Portal to manage their own subscription details.
View Advisor Dashboard
What
Opens the main advisor hub — a four-tab interface consolidating all advisor tools. Sailings contains the Itinerary Timeline (with "Port Guide →" quick-link to Port Tools per cruise), Who's Sailing summary cards (with "View itinerary ↗" links), Act Now queue, Cruise Change Feed, Intelligence panel, and Port Activity. Clients contains the full Traveler Roster (with add/import forms, archive toggle, and + Cruise action) and (for Travefy advisors) the Travefy link editor. Port Tools contains Port Guide lookup (including Port Day at a Glance for V4 ports), DOCK Diagnostics, Congestion Calendar, Port Utilization, and Guide Settings. Settings contains Travefy Sync (Travefy advisors only) and Notification Preferences. Old URL params (?tab=roster) remap to clients; ?tab=travefy, alerts remap to settings; ?tab=actnow, intelligence remap to sailings.
Who
Authenticated advisor, at /agent-dashboard.
Result
Central access point for every advisor capability in DockBound.
Sailings Tab — Act Now Section
View Act Now Queue
What
Displays a ranked, prioritized list of the most urgent advisor actions across all active client trips — imminent port arrivals, at-risk ports, clients sailing this week with undelivered guides.
Who
Advisor, on the Sailings tab — Act Now section.
Result
Advisor immediately knows what to work on first without manually scanning the full roster.
View Cruise Change Feed
What
Displays a rolling feed of cruise itinerary changes detected by DockBound's CruiseMapper pipeline — new sailings, itinerary updates, deletions, and reappearances. When the advisor has Travefy enrichments, changes matching ports in their tracked trips surface first under a "Relevant to your trips" callout with teal highlighting and port name pills; all other changes appear below as "Other changes."
Who
Advisor, on the Sailings tab — Act Now section.
Result
Advisor immediately spots itinerary changes that affect clients at their tracked ports without manually cross-referencing the change log.
Sailings Tab — Intelligence Section
View Today's Ports
What
Aggregates every port call happening today across all active client trips and displays them in a single consolidated view with DockScore and conditions for each.
Who
Advisor, on the Sailings tab — Intelligence section.
Result
Advisor sees at a glance which clients are in port today and what conditions they're facing.
View Next 3 Days
What
Lists all upcoming port calls within the next three days across all client trips, organized into date buckets.
Who
Advisor, on the Sailings tab — Intelligence section.
Result
Advisor can prepare client outreach and guide delivery for imminent arrivals.
View At-Risk Itineraries
What
Scans all active trips and flags any port where the dynamic DockScore exceeds the static baseline by 0.5 or more — a meaningful degradation in port conditions. Flagged ports are highlighted in red.
Who
Advisor, on the Sailings tab — Intelligence section.
Result
Advisor can proactively contact clients about ports where conditions are significantly worse than normal, before the client experiences them.
View Port Activity
What
Groups all cruise changes detected in the last 30 days by port, filtered to only the ports present in the advisor's Travefy-enriched trips. Each port group shows a change count badge sorted highest first, with type badges, cruise identifiers, changed fields, and detection dates for each entry. Hidden when the advisor has no Travefy enrichments.
Who
Advisor with Travefy enrichments, on the Sailings tab — Intelligence section.
Result
Advisor sees at a glance which ports on their tracked itineraries have been most volatile recently, enabling targeted proactive client outreach.
Sailings Tab — Who's Sailing Section
View Itinerary Timeline
What
A grouped table of all cruise sailings across the advisor's roster, sorted by temporal urgency. Urgent rows (Sailing Now / This Week) appear first with colored highlights; remaining sailings are grouped under month-year bucket headers. Each row shows cruise name, ship, departure port, sail date, status pill, client count, and a "Port Guide →" quick-link that switches to the Port Tools tab with the first port of call pre-selected.
Who
Advisor, on the Sailings tab — Who's Sailing section.
Result
Quick scan of the entire forward sailing calendar, grouped by cruise and sorted by urgency — one row per cruise+sailDate combination regardless of how many clients are on that sailing. One click reaches the port guide for the first port without navigating away.
View Who's Sailing Summary Cards
What
Below the Itinerary Timeline, individual CruiseCards are shown for urgent sailings (Sailing Now and This Week) providing richer detail: cruise name, ship, departure port, duration, sail date, status pill, a client count link to the roster, and a "View itinerary ↗" link that opens the full cruise itinerary printable view at /print/cruise/:cruiseId in a new tab.
Who
Advisor, on the Sailings tab — Who's Sailing section.
Result
At-a-glance spotlight on the most time-sensitive sailings with enough detail to act; the itinerary link lets the advisor quickly share or review the full sailing schedule without navigating away.
Port Tools Tab — Congestion Calendar Section
View Port Congestion Calendar
What
Renders a forward-looking heatmap showing port congestion levels across all tracked sailings — which ports and dates are projected to be busiest.
Who
Advisor, on the Port Tools tab — Congestion Calendar section.
Result
Advisor can spot high-congestion dates in advance and set expectations with clients before they embark.
Port Tools Tab — Port Guide & DOCK Section
Look Up Port Guide
What
Lets the advisor search for and display the full port guide content for any port in the DockBound database — the same content their clients will see in their DOCKGuide.
Who
Advisor, on the Port Tools tab — Port Guide & DOCK section.
Result
Advisor can review and validate the exact port guide their client will receive, and answer client questions with confidence.
View Port Day at a Glance
What
The first section of each port guide (for ports with V4 schema data), surfacing a badge row of cruise-intelligence fields: port type chip, activity depth (Low/Moderate/High/Very High), major experience transfer time, return complexity (Easy/Plan Ahead/Complex with semantic color coding), taxi pricing estimate, and a single high-priority "impact action" callout — the one thing the traveler must act on for this port. All data comes from V4 doc-level fields (portAreaActivityDepth, returnComplexity, impactAction, majorExperienceTransferTime, returnDependencies). The section is hidden if the port has no V4 data.
Who
Advisor (in the Port Tools tab) or traveler (in their DOCKGuide), wherever the port guide is displayed.
Result
At-a-glance logistical intelligence for the port day — before the advisor or traveler reads a single paragraph of guide prose.
View DockScore
What
Displays both the static baseline and live dynamic DockScore for a selected port, including the delta between them and a red risk flag when the delta is ≥ 0.5.
Who
Advisor, on the Port Tools tab — Port Guide & DOCK section.
Result
Advisor has a precise read on current port conditions and can contextualize them accurately for clients.
View DOCK Diagnostics
What
Shows the complete breakdown of every signal contributing to a port's DockScore, labeled by data source with icons per driver.
Who
Advisor, on the Port Tools tab — Port Guide & DOCK section.
Result
Advisor can explain exactly what is driving port conditions to any client who asks.
Clients Tab — Roster Section
Add Traveler Manually
What
Opens a form to add a single client to the advisor's roster: name, email, cruise (chosen from a filterable picker by cruise line, ship, or sail date), and optional phone number and booking reference ID.
Who
Advisor, on the Clients tab — Roster section.
Result
Client added to the roster; one slot consumed from the advisor's plan capacity; client status set to pending.
Import Travelers via CSV
What
Accepts a CSV file upload with columns (name, email, cruise_id, optional phone, optional reference_id). DockBound validates each row against the cruise database — showing a preview of valid vs. skipped rows — before the advisor confirms the import.
Who
Advisor, on the Clients tab — Roster section.
Result
All valid rows added to the roster in bulk; a summary reports how many were imported vs. skipped with a reason for each skip.
View Team Roster
What
Displays the advisor's full active client list as a table, each row showing name, email, phone, assigned cruise, and status (pending / active / expired). Row actions include Messages (opens communication thread), + Cruise (opens the cruise picker to update or add a cruise to the roster entry), and Archive. A "Show archived travelers" toggle at the bottom of the table reveals a separate archived section.
Who
Advisor, on the Clients tab — Roster section.
Result
Complete view of every active client the advisor is currently managing, with one-click access to contact history, cruise assignment, or archiving for any traveler.
Archive / Unarchive Traveler
What
Soft-deletes a roster entry by setting its archived: true flag in Firestore. The entry is hidden from the main roster view but can be revealed via the "Show archived travelers" toggle. Archived entries can be unarchived at any time, which restores their slot consumption and visibility. This replaces the previous hard-delete "Remove" action.
Who
Advisor, on the Clients tab — Roster section, via the Archive button on a roster row.
Result
Client entry moved to the archived section; slot freed for active capacity. No Firestore data is permanently deleted — the record is recoverable.
Add Cruise to Roster Entry
What
Opens the Cruise Picker modal on an existing roster entry, allowing the advisor to assign or update the cruise associated with that traveler. The cruise picker filters by cruise line, ship, and sail date.
Who
Advisor, via the "+ Cruise" button on a roster row (both active and Travefy-linked roster sections).
Result
Roster entry updated with the selected cruise; sail date and ship name stored on the entry for use by the Itinerary Timeline and intelligence panels.
Open Traveler Communication Thread
What
Opens a right-side drawer for a specific traveler, showing the full history of all correspondence with that client — in-app messages, logged emails, logged calls, logged SMS, and notes — in chronological order.
Who
Advisor, via the Messages button on a roster row.
Result
Advisor sees every past touchpoint with that client in one view; any unread messages are automatically marked read and the thread's unread count resets to zero.

System-triggered nightly; no user action required.
Result
All connected advisors' intelligence dashboards reflect current Travefy data at the start of each business day.
Travefy Platform Echo
What
Admin diagnostic function that sends a test call to the Travefy API using DockBound's platform credentials to verify the platform-level connection is healthy and returning expected responses.
Who
Admin, via a direct Cloud Function invocation.
Result
Confirmation that the Travefy platform integration is operational; used to troubleshoot connection or credential issues.
Travefy Authorized Users
What
Admin function that queries the Travefy API to return a list of all users who have authorized DockBound platform access, along with each user's connection status.
Who
Admin, via a direct Cloud Function invocation.
Result
Complete visibility into which advisors have active Travefy connections through DockBound's platform authorization.
Resolve Node Permissions
What
Calculates the effective section-level permissions for a user based on their role, subscription tier, and advisor configuration — then caches the computed permission map directly on the user's Firestore document for fast dashboard rendering.
Who
Cloud Function triggered on user login.
Result
Cached permission map available on the user doc; the useEffectivePermissions hook reads it instantly to show or hide guide sections without an additional network call.
Send Traveler SMS
What
Authenticated Cloud Function (sendTravelerSms) that accepts an advisor's ID token, a thread ID, and a message body. Verifies the caller is the thread's owning advisor, sends the SMS via the Twilio REST API from the DockBound platform number, and writes the outbound message record to Firestore.
Who
Called by the advisor's browser when sending an outbound SMS from the communication thread drawer.
Result
SMS delivered to the traveler's phone; outbound message logged to agentCommunications/{threadId}/messages.
Twilio Inbound Webhook
What
Public Cloud Function (twilioInboundWebhook) registered as the Twilio messaging webhook URL. Validates the X-Twilio-Signature header (HMAC-SHA1) — rejects all requests if the auth token is not configured (fail-safe). Handles two inbound message types: (1) Keyword SMS — if the message body is the word JOIN (case-insensitive), the function auto-generates a DOCK-XXXX-XXXX invite code (or resends the existing code if the phone already has one — idempotent), stores it in invite_codes with source: 'sms' and sourcePhone fields, and replies via TwiML with the code and signup URL. (2) Thread replies — for all other messages, matches the sender's phone number to a traveler's communication thread in Firestore and writes the inbound message as a new record with senderRole: traveler.
Who
Called by Twilio when any inbound SMS arrives at the DockBound platform number. No user action required.
Result
For keyword JOIN: prospective advisor receives an invite code by SMS reply. For traveler replies: message appears in the advisor's communication thread in real time; thread's unread count increments by 1.
Send Advisor Alert Digest
What
Scheduled Cloud Function (sendAdvisorAlerts) that runs daily at 8am ET. Queries all advisors with email alerts enabled, matches changes since each advisor's lastAlertSentAt to their tracked ports via travefyEnrichments, and sends a per-port grouped HTML email via SendGrid. Updates alertSettings.lastAlertSentAt on each agent document after sending.
Who
System-triggered on schedule at 8am ET. No user action required.
Result
Each subscribed advisor receives a morning digest of overnight cruise changes at their tracked ports, matched by port code to their Travefy enrichment records.
Trigger Advisor Alerts (Admin)
What
Admin-only HTTP Cloud Function (triggerAdvisorAlerts) that manually invokes the same advisor alert logic as the daily scheduled run — for testing the alert pipeline without waiting for 8am ET. Requires an admin or super-admin Firebase ID token.
Who
Admin, via a direct Cloud Function invocation or an admin-facing test button.
Result
Alert emails sent as if it were the daily scheduled run — useful for verifying the SendGrid integration, email templates, and port-matching logic after any changes.
QA Section Trigger (onSectionWriteQA)
What
Firestore document trigger on locations/{locationId}/sections/{sectionKey} writes. When new content arrives (and inline QA was not already run), validates the section against shared/portGuideValidator.js rules, writes a result doc to content_qa_results, and stamps qaStatus (approved | approved_with_advisories | human_review_required) back onto the section doc. Skips deletions and re-fires on its own writes via the qaValidation guard.
Who
System-triggered on each section write. No user action required.
Result
Every section written to Firestore is automatically validated; sections with critical issues are immediately flagged for human review in the QA Review tab.
Export Regression Fixture (adminGetRegressionFixture)
What
Admin Cloud Function that fetches a QA result and its associated section content, packaging them as a downloadable golden fixture scaffold (JSON) for use in the regression test suite. The fixture includes a _meta block with humanApproved: false — admin must manually review and set to true before adding to src/test/fixtures/portGuides/. Admin-only via Firebase ID token.
Who
Admin, via the "Download Fixture" button in the QA Review tab.
Result
A JSON fixture scaffold downloaded to the admin's browser, ready to be reviewed and added to the regression test suite.
