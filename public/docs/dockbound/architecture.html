1. System at a Glance

DockBound is a cruise port intelligence platform. Travel advisors use it to prepare clients for the real logistics of a port day — timing, friction, conditions, and what could go wrong — packaged into shareable DockGuides. The platform also monitors itinerary changes, integrates with Travefy, and exposes a versioned partner API.

State Management

No Redux or Zustand. State is colocated at the component level or lifted to the nearest ancestor. Two context providers wrap the app:

  • AuthContext (contexts/authContextCore.tsx) — Firebase Auth state + onAuthStateChanged. Use useAuth() to read currentUser.
  • UserProfileContext (implicit in useUserProfile hook) — Firestore user doc including role and effectivePermissions.

Firebase Imports: Eager vs. Lazy

Rule: use lazyFirebase.ts (async getters) for services not needed on the initial page load. Use firebase.ts (eager, synchronous) only for components that always need Auth/Firestore immediately (AuthContext, communicationsService).

Design System

The app uses light mode only. Dark mode is disabled (media query commented out in src/index.css pending full QA). There is no Tailwind CSS. All color tokens are CSS custom properties defined in src/index.css.

  • Never hardcode color values in inline styles. Always use a --color-* variable.
  • Add class="on-dark" to any element with a dark/navy/gradient background — children read the same CSS vars, no style branching needed.
  • Content cards: background: var(--color-surface), border: 1px solid var(--color-border), box-shadow: var(--shadow-sm). No gradient backgrounds on content cards.
  • Status colors: use semantic pairs — danger → --color-danger + --color-danger-background; etc.
  • DOCK chip colors: CSS vars --dock-chip-* in src/index.css.

4. Cloud Functions Backend

Structure

All Cloud Functions live in a single file: functions/index.js (ESM, Node 22). There is no function-per-file structure.

Function Types Used

TypeFirebase APIUsed for
HTTP endpointonRequestAll client-facing calls, webhooks, partner API
Cron jobonScheduleItinerary change polling, advisory refresh
Firestore triggeronDocumentUpdated, onDocumentCreatedPost-write side effects (enrichment triggers, etc.)

Auth Pattern for HTTP Functions

The frontend calls Cloud Functions via fetch with a Firebase ID token:

Authorization: Bearer <Firebase ID token>

Functions decode the token using the Admin SDK (admin.auth().verifyIdToken()) to get the caller's UID and role. Admin-only functions additionally verify the role from Firestore before proceeding.

Base URL

All CF calls use the shared base URL pattern:

VITE_FIREBASE_FUNCTIONS_URL = https://us-central1-PROJECT.cloudfunctions.net # Frontend calls: fetch(`${FUNCTIONS_URL}/functionName`, { ... })
Do NOT restructure to per-function URLs. The shared base URL is intentional — all services read from the same env var.

Secrets

Sensitive keys are stored in Firebase Secret Manager and declared with defineSecret() at the top of functions/index.js. They are never in env files or source code.

5. Firestore Data Model

Collections are listed alphabetically. Each entry shows the document ID pattern, key fields, and which system owns it.

agents/{uid}

One doc per travel advisor. Created by registerAdvisorRole CF at signup.

  • uid, email, displayName, role
  • travefyConnection — set by travefyConnect CF (accessToken, etc.)
  • stripePriceId, stripeSubscriptionStatus, trialEndsAt
  • agencyId — if the advisor belongs to an agency host
  • Sub-collection: agents/{uid}/trips — Travefy trip cache

agentCommunications/{agentId}_{rosterId}

Thread metadata for advisor-traveler messaging. Sub-collection messages holds individual messages.

agentPortConfig/{uid}

Per-advisor port guide customization (welcome message, port overrides). Firestore rule allows read on non-existent docs (resource == null) so first-time reads don't 403.

agentRoster/{rosterId}

Traveler enrollment records. One doc per advisor-traveler pairing.

  • agentId, travelerUid (may be null if not yet linked), name, email, phone, refId
  • cruiseId, cruiseName, shipName, sailDate, departurePort
  • archived (boolean) — soft-delete only; never hard-delete roster entries
  • travefyTripId — optional Travefy trip link

api_keys/{8hexId}

Partner API key records. Full key is never stored — only the SHA-256 hash.

  • keyHash (SHA-256 hex), active (bool), plan (sandbox|paid)
  • label, owner, note, createdAt
  • Key format: dbk_{8hexId}_{secret}

config/stripe

Firestore-stored Stripe config (not secrets). Includes webhookSecret read at runtime by the stripeWebhook CF.

content_qa_results/{locationId}_{sectionKey}_{epoch}

QA results from the AI content validator. One doc per flagged section per generation run. Read by the Content Health admin page.

cruises/{cruiseId}

Cruise schedule data. Written by the Apify scraper. Key fields: cruiseLine, shipName, sailDate, itinerary (array of port stops), is_future_sailing.

dock_scoring_rules/{ruleId}

40+ static + dynamic DOCK scoring rules. Seeded from CSV via npm run dock:import-rules:dev. Quarterly review — do not modify without evidence from advisor feedback.

dock_scores_baseline/{portCode}

Baseline (static) DOCK scores computed from port guide JSON fields. Regenerated manually: npm run dock:regen-baselines:dev. Do not automate — cost control.

dock_scores_adjusted/{portCode}_{sailDate}

Dynamic DOCK scores cached after the dockCalculateAdjusted CF applies modifiers (ship count, weather, advisories). Client reads from this collection; CF regenerates on demand.

invite_codes/{docId}

One-use advisor signup codes in DOCK-XXXX-XXXX format. Managed from /admin/invite-codes. Validated by the validateInviteCode CF at signup to prevent orphaned auth accounts.

locations/{locationId}

Location master records. Sub-collection sections/{sectionKey} holds normalized, section-keyed port guide content. This is a legacy path — PlatformCore is now the primary source. qaStatus on each section doc tracks AI content review state.

port_guides/{portCode}

Flat legacy port guide docs (deprecated fallback path). Still served as fallback when PlatformCore CF call fails. Schema versions V1–V4; see Port Guide Pipeline.

port_schedule/{portCode}_{YYYY-MM-DD}

Ship counts per port per day. Built from the cruises collection by npm run dock:build-schedule:dev. Powers DOCK O/D dynamic adjustments and port congestion calendar. Rebuild monthly.

sectionTypes/{key}

Live catalog of port guide section keys. The TypeScript type PortSectionKey in src/types/locations.ts mirrors this.

travefyEnrichments/{agentUid}_{tripId}_{portCode}

Deduplication log for Travefy enrichment writes. One doc per advisor+trip+port combination; prevents duplicate TripEvents in Travefy.

users/{uid}

User profile docs. Managed by Firebase Auth triggers + Admin SDK (role writes bypass Firestore rules).

  • role — see Auth & Role System; client cannot write this field
  • effectivePermissions — written by resolveNodePermissions CF at login; cached section visibility + tier
  • agentId, agencyId — linkage fields; client cannot write these

Roles cannot be self-promoted. Firestore rules block client writes to role, agentId, and agencyId fields. Role assignment always goes through Admin SDK in a Cloud Function.

Route Guards

  • ProtectedRoute — reads useUserProfile(), checks role flags, redirects unauthenticated users to /auth.
  • AdminRoute — slim wrapper that only checks isAdmin flag.

Advisor Self-Service Signup

User visits /auth?mode=signup&advisor=true │ ├── DocBoundAuth detects isAdvisorSignup from query param ├── Shows advisor-flavored form (name, email, password, invite code) ├── Calls validateInviteCode CF → checks invite_codes collection → marks code used ├── Creates Firebase Auth account ├── Calls registerAdvisorRole CF with ID token │ └── Admin SDK sets role: 'independentAdvisor' on users/{uid} │ (bypasses Firestore rules that block client-side role writes) └── Redirects to /agent-dashboard → Stripe plan picker + trial gate

Effective Permissions

At login, the resolveNodePermissions CF writes effectivePermissions onto users/{uid}. This cache tracks section visibility and subscription tier (free | paid). The FeatureGate component gates rendering based on this tier — no inline role checks scattered through components.

7. Port Guide Pipeline

Source of Truth: PlatformCore

PlatformCore is the primary source for all port guide content. The local Firestore port_guides collection is a deprecated fallback — it is only served when the PlatformCore CF call fails.

8. DOCK Scoring System

DOCK = Distance Friction + Operational Load + Conditions + Key Risks. Each dimension is scored 1–5 and combined into a weighted overall score.

Two-Layer Architecture

Layer 1: Baselines (static) dock_scores_baseline/{portCode} └── Computed from port guide JSON fields └── Regenerated manually: npm run dock:regen-baselines:dev └── Script: scripts/regenerate-dock-baselines.cjs └── Do NOT automate — cost control Layer 2: Adjusted (dynamic) dock_scores_adjusted/{portCode}_{sailDate} └── dockCalculateAdjusted CF applies modifiers: ├── Ship count (from port_schedule) ├── Weather (OpenWeather API) └── Travel advisories (State Dept. CF) └── computeDockAdjusted() helper is extracted and shared across API endpoints └── Results cached in dock_scores_adjusted

Scoring Rules

40 static + dynamic rules in dock_scoring_rules. Seeded from CSV: scripts/archive/dock-scoring/dock-scoring-rules-corrected.csv.

npm run dock:import-rules:dev # requires ADC (Application Default Credentials) npm run dock:import-rules:prod

Client-Side View: EnrichedPortScore

Defined in src/types/agentTrips.ts. Fields the UI consumes:

FieldTypeMeaning
staticAvgnumberBaseline score (from dock_scores_baseline)
dynamicAvgnumberAdjusted score (from dock_scores_adjusted)
deltanumberdynamicAvg − staticAvg
opStatestringRelaxed | Manageable | Elevated | High-Constraint

isAtRiskbooleantrue when delta ≥ 0.5

Port Schedule Index

Rebuild monthly after cruise data updates:

npm run dock:build-schedule:dev # then verify, then: npm run dock:build-schedule:prod

UI Entry Point

The DatabaseDockDiagnostic component is the UI entry point for System 2 scoring. AgentIntelligencePanel (src/pages/AgentIntelligencePanel.tsx) shows port-day cards with static/dynamic scores, op-state badges, AT-RISK flags, and driver icons for the advisor's sailing timeline.

9. Travefy Integration

Overview

Travefy is an itinerary management platform used by many travel advisors. DockBound integrates two ways: pulling trip data in, and writing DockBound intelligence events back out.

Advisor connects Travefy account │ └── travefyConnect CF: links by email, stores accessToken in agents/{uid}.travefyConnection Advisor syncs trips (Settings tab → Travefy panel) │ └── travefyTrips CF: fetches trips from Travefy API, enriches each port stop with DOCK baseline + port guide, stores in agents/{uid}/trips (Firestore cache) ⚠ Frontend reads from this cache — advisor must sync before Travefy links appear Advisor clicks "Enrich Travefy" │ └── travefyEnrich CF: writes DockBound TripEvent (EventType 12) per port day ├── Deduped by PartnerIdentifier: "dockbound-{portCode}" ├── Prefers adjusted DOCK score within 14 days of sailing ├── Description: HTML format (<b><big> headings, <br><br> paragraphs) └── Logged in travefyEnrichments/{agentUid}_{tripId}_{portCode}

10. Partner API

Key Format

External API keys use format dbk_{8hexId}_{secret}. Only the SHA-256 hash of the full key is stored in Firestore. Cloud Functions validate via Admin SDK — the client SDK cannot access api_keys.

Endpoints

  • sandbox — limited response (first 5 sections, baseline score only). Rate-limited.

Admin UI

API keys are managed at /admin/api-keys (ApiKeyAdminPage). Create (Web Crypto keygen + SubtleCrypto SHA-256), revoke/restore, delete. Full key is shown once at creation and never retrievable again.

12. Payments & Subscriptions

Flow

Advisor selects plan tier (plan picker UI) │ └── stripeCreateAgentSubscriptionSession CF ├── Creates Stripe Checkout session (server-side) ├── Returns session URL └── Frontend redirects to Stripe-hosted checkout Payment completes │ └── stripeWebhook CF (verifies stripe-signature via constructEvent) ├── checkout.session.completed → audit log └── charge.dispute.created → sends email alert via SendGrid Trial gate └── trialEndsAt (on agents/{uid}) vs. now └── If expired + no active subscription → upgrade banner/blocker in dashboard

Pricing Tiers

Independent advisors use the same tier config as Travefy advisors (TRAVEFY_TIERS) — designed to be swapped out for INDEPENDENT_ADVISOR_TIERS when pricing diverges.

Webhook Config

  • Webhook secret stored in Firestore config/stripe.webhookSecret (read at runtime, not hardcoded)
  • Email failure logged but does NOT return non-200 — prevents Stripe retry storms
  • Register CF URL in Stripe Dashboard → subscribe to charge.dispute.created + checkout.session.completed

17. Engineering Conventions

Code Style

  • No any casts — prefer typed interfaces; any only in legacy adapter code
  • Unused vars — prefix with _ to suppress ESLint (argsIgnorePattern: '^_')
  • ESLint — flat config (eslint.config.js); functions/ and scripts/ are excluded
  • Firestore Timestamps — always write with serverTimestamp(); convert on read with .toDate()
  • No comments by default — only add when the WHY is non-obvious (hidden constraint, surprising behavior, known bug workaround)

Scope Discipline

  • Do not refactor unrelated working code — a bug fix is not a refactor ticket
  • Do not change existing product behavior unless the task explicitly requires it
  • Build the smallest reliable system that meets requirements
  • Do not add a large dependency when a small implementation in the existing stack is sufficient

AI-Generated Content Rules

  • Never treat AI-generated output as human-approved ground truth — label synthetic fixtures clearly
  • Never silently invent scoring logic, rules, or thresholds — create a clearly named placeholder instead
  • Missing evidence must produce uncertainty, not fabricated certainty

Admin Pages Color Exception

ContentHealthPage, RemindersAdminPage, and InviteCodesPage use hardcoded hex/rgba colors (Slate/Indigo palette) without CSS vars. Decision pending: migrate to CSS vars + .on-dark wrapper, or document as intentional dark admin-only pages.
