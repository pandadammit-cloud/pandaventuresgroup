1. Product Overview

ForumJourney is a white-label event readiness API that helps attendees arrive prepared — on time, with the right information, zero last-minute surprises. Partners (event organizers) integrate once via API and ForumJourney automatically generates and maintains attendee plans for every event occurrence.

Zero friction for attendees

A single link, no login, shows everything they need — from travel options to bag policy to live parking intelligence.

Real-time sync

When event details change, ForumJourney detects it automatically and notifies attendees through the partner.

Personalized plans

Stage-aware content adapts from early registration through day-of attendance — right information at the right time.

Multi-role portals

Organizers, venue staff, and speakers each get a dedicated warm portal — agenda management, guide edits, presentation upload, special requests.

2. Integration Model

Partners integrate once and ForumJourney handles ongoing plan generation and change detection automatically.

  1. Partner registers and receives an API key
  2. Partner creates Events and Occurrences via the REST API
  3. Partner adds Attendees to Occurrences
  4. ForumJourney generates stage-aware plans and returns plan URLs
  5. Attendees receive their plan URL (via partner's existing communication channel)
  6. When event details change, partner POSTs an update to ForumJourney
  7. ForumJourney detects material changes and fires a forumjourney.plan.changed webhook to the partner
  8. Partner notifies attendees using the included pre-formatted notification strings

3. The Attendee Plan

Plans are stage-aware — content adapts automatically based on how far away the event is. The stage is computed at plan generation time. Per-partner stageThresholds can override the global defaults.

4. Change Detection & Notifications

When a partner POSTs an event update to ForumJourney, the platform automatically handles detection, notification generation, and delivery:

  1. ForumJourney diffs the incoming data against stored values using a field whitelist
  2. Material changes (status, admission policy, session times, bag policy, etc.) create Change documents
  3. Affected plans are marked stale immediately
  4. ForumJourney fires a forumjourney.plan.changed webhook to the partner's registered URL
  5. Each webhook payload includes notificationContent with two pre-formatted notification strings

Notification Content Variants

VariantGenerationBest For
FactualRule-based, deterministicSMS, push notifications — precise and safe
ConversationalClaude claude-haiku-4-5 generatedEmail, in-app — warm and human-sounding

Partners control when and how to surface notifications to attendees. ForumJourney stores per-attendee notificationPreference (off / factual / conversational) as a hint for partners.

Inbound Webhook Security

Partner-sent updates to POST /v1/webhooks/partner-events must include:

  • X-ForumJourney-Signature — HMAC-SHA256 of the raw request body using the shared inboundWebhookSecret
  • Timestamp in payload — validated within ±5 minutes (replay protection)
  • Idempotency key — prevents duplicate processing on retries

6. Attendee Experience

Attendees receive a URL of the form [domain]/plan/{occurrenceId}. No login or account required.

Plan Page — What Attendees See

  • ForumJourney logo and event header with key details
  • Stage-appropriate content sections (auto-selected based on days until event)
  • Venue guide sourced from Firestore: in-the-know tips, getting-there options, arrival advice
  • City guide: transit, neighborhoods, local tips (Firestore)
  • Discoveries: nearby parking facilities with open-now status, ratings, EV charging info (when collected)
  • Weather summary with NWS alerts (prepare and attend stages)
  • All content is read-only; no attendee account or login

Join Flow

Attendees can self-register by entering a join code (distributed by organizer) at /join. The 5-state flow handles: new registration, linking an existing account, duplicate registration, full events, and invalid codes. On success, the attendee gets a Firebase Auth account and is redirected to their portal.

Plan URL: Plans are accessible at forumjourney.app/plan/{occurrenceId} (production) and eventbound-dev.web.app/plan/{occurrenceId} (development).

9. Platform Intelligence

ForumJourney enriches partner-supplied event data with multiple layers of external intelligence:

SourceContentSurfaced In
Venue guide (Firestore)Hand-curated: getting-there options, in-the-know tips, arrival calm factor, building layout. Edited by venue staff via portal.Public plan page, all stages
City guide (Firestore)Hand-curated: transit, neighborhoods, local tips, emergency contacts. 11 cities seeded.Public plan page, all stages
OpenWeatherMapCurrent conditions (attend stage) + 5-day forecast (prepare stage). NWS active alert overlay.Plan content weatherAndConditions
Data collection pipelineGoogle Places parking adapter: nearby parking facilities with open-now, rating, EV charging. Stored as normalizedFacts.Plan content discoveries[] (plan/prepare/attend stages)
OpenStreetMap adapterVenue and city enrichment from OSM data.Venue + city Firestore records (background enrichment)
Data collection pipeline architecture: The Collect → Surface → Manage model separates data gathering (adapters → normalizedFacts) from consumption (plan generator reads facts → discoveries[]). Parking is the first fully end-to-end category. Additional categories (transit, dining, activities, etc.) follow the same pattern — add an adapter, add a normalizer, and facts flow automatically into plans.
