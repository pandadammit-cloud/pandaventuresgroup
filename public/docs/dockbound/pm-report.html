Lessons Learned (new this run)

2026-09-14 — Firestore batch DEADLINE_EXCEEDED with large text payloads

Seeding rawFieldData with ~55K observations at batch size 400 hit Firestore's 60-second commit deadline after ~1,400 ports. Each observation doc contained multi-paragraph text fields, making the deadline tight. Fix: cap chunk size at 50 for text-heavy collections and add retry with exponential backoff for gRPC codes 4 (DEADLINE_EXCEEDED) and 14 (UNAVAILABLE). The 500-operation limit is an upper bound — large payloads demand much smaller chunks in practice.

2026-09-14 — Seed script idempotency should operate at document level, not field level

Per-field idempotency checks (N×M reads) stall on large collections. The correct pattern: call listDocuments() once on the parent collection to build a Set<string> of already-seeded document IDs, then skip at document level. This reduces overhead from O(N×M) sequential reads to one batch read + O(1) Set lookup. Apply to any seed script that re-runs over a large collection.

2026-09-14 — E2E specs go stale when dashboard tabs are renamed or consolidated

The H8 PM audit found 4 specs (Flow10, Flow12, Flow13, Flow19) referencing tab names that no longer exist after the 6→4 dashboard tab redesign. The specs timed out rather than erroring clearly — hard to debug. Pattern: after any tab restructure, grep tests/acceptance/ for hasText: patterns matching old tab labels. The H8 PM hook now automates this check every run.
