0 Program Charter — write first 1 item
Write Privacy Program Charter Overarching document describing the scope, governance model, controller/processor determination, applicable laws, and DockBound's stated approach to each compliance obligation area. Written before operational work begins — serves as the entry point for auditors, investors, or regulators. The Art. 30 records, DPIA, policies, and tooling are the evidence that the charter has been executed. Reference doc: docs/privacy-program-charter.html.

Maintain Art. 30 records as a living document (assign owner + review cadence) Art. 30 requires records of processing to be kept current — not a one-time artifact. Assign an owner and a review cadence (e.g., quarterly or on each new data collection change).

2 Lawful Basis & Consent 5 items
Define lawful basis per data category Likely: contract for account/booking data, consent for marketing, legitimate interest for fraud/security logging. Document in the Art. 30 records.
gdpr-2-1S
Cookie/tracking consent banner — opt-in for EU visitors (not opt-out) If using analytics, ad pixels, or non-essential cookies: add a consent banner that is opt-in for EU visitors. Confirm what cookies/tracking are in use across all product surfaces.
gdpr-2-2M
Consent capture: granular, timestamped, easily withdrawable Consent must be granular (per purpose), logged with timestamp, and trivially withdrawable. Withdrawal must be as easy as giving consent.
gdpr-2-3M
CSV roster uploads: determine controller vs. processor role When Compass agents upload client rosters via CSV, clarify whether DockBound is a controller or processor for that client data. Determines whose consent/notice obligations apply and what must appear in agency terms of service.
gdpr-2-4S
Confirm no under-16 data collection; document determination Age-gating/parental consent likely not required (B2B + adult consumer travel product). Confirm with counsel and document the determination.

3 Data Subject Rights — Implementation 9 items · largest engineering lift
Right to access: build cross-platform data export function Build an export function that pulls a user's data across Firestore (profile, bookings/searches, agent overrides if applicable), Stripe customer record, and any Travefy-pushed content tied to that user.
gdpr-3-1L
Right to erasure: consumer account deletion cascade (Firestore, Stripe, Twilio) Consumer account deletion must remove or anonymize: Firestore user doc, Stripe customer record (or retain only minimum data required for tax/legal), and any Twilio message history. Build a cascading deletion Cloud Function.
gdpr-3-2L
Right to erasure: confirm port/ship pipeline is scoped out (not personal data) Confirm erasure does NOT need to touch the port/ship data pipeline — that is not personal data. Document this scoping decision so the erasure logic is narrow and defensible.
gdpr-3-3S
Right to erasure: agent guide overrides — delete full delta record (not just base reference) Agent overrides are stored as delta records (agentGuideOverrides). Confirm delete logic removes the delta record entirely, not just the base profile reference. Test erasure of all subcollections (customSections, etc.).
gdpr-3-4M
Right to rectification: confirm existing profile edit flows satisfy requirement No gap expected — existing profile edit flows should count. Confirm and document the determination.
gdpr-3-5S
Right to data portability: structured machine-readable export (JSON) Provide data export in a structured, machine-readable format (JSON). Can bundle with the access-request export (gdpr-3-1). Format must be interoperable — not proprietary.
gdpr-3-6M
Right to object/restrict: suppression flag for non-essential processing Build a flag mechanism to suppress a user's data from non-essential processing (marketing, analytics) without full deletion. Must be persisted in Firestore and honored by all processing paths.
gdpr-3-7M
Build internal DSR admin tool for support staff (30-day SLA) Single internal admin tool or Cloud Function so support staff can execute access/erasure/export requests without manual Firestore digging. Target SLA: 30 days under GDPR.
gdpr-3-8L
DSR B2B determination: host-submitted vs. advisor self-serve Decide DSR handling for B2B tiers: does a Helm host network or Chartroom agency submit requests on behalf of their agents, or do individual advisors self-serve? Affects DSR tool design and agency terms of service.

§ 11 — US Addendum: State Privacy Laws (CCPA/CPRA + Multi-State Baseline)

The DSR tooling built for GDPR (§3) covers ~90% of what these state laws require. This section is the delta on top. 24 states have comprehensive consumer privacy statutes as of August 2026.

11.1 Applicability Check 3 items
Determine which state privacy law thresholds DockBound meets or is likely to meet Assess current and projected user counts and revenue against each state's threshold. Revenue and consumer-count thresholds vary widely (e.g., Texas has no revenue threshold; Florida's is $1B+). Document which laws apply now and at what scale milestones new ones trigger.
gdpr-11-1-1S
Priority state analysis: CA (CCPA/CPRA), TX (TDPSA), CO (CPA), CT (CTDPA), IL (BIPA) Priority states given a nationally-sold consumer product: California (CCPA/CPRA — sets the practical ceiling), Texas (TDPSA — broad applicability, no revenue floor), Colorado (CPA — highest per-violation penalties), Connecticut (CTDPA), and Illinois (BIPA if any biometric data is ever collected).
gdpr-11-1-2S
Track actual user base concentration per state for ongoing threshold monitoring Thresholds are per-state — a state with heavy DockBound usage can trigger obligations even if it is not on the priority list. Build or identify a way to track registered user counts by state and review annually.
gdpr-11-1-3S
11.2 Consumer Rights — Delta on Top of GDPR DSR Tooling 5 items
Opt-out of "sale"/"sharing": audit all analytics and data-sharing integrations CCPA defines "sale" broadly (including some ad-tech data sharing). Audit whether any current or planned integration (analytics, ad pixels, Travefy data sharing) could count as a "sale" under this definition.
gdpr-11-2-1M
Add "Do Not Sell or Share My Personal Information" link if applicable Required on the consumer-facing site if any sale or sharing occurs. Determine applicability from the audit (gdpr-11-2-1), then add the link with the appropriate opt-out mechanism.
gdpr-11-2-2M
Implement Global Privacy Control (GPC) signal recognition in consent layer California requires automatically honoring browser-level GPC opt-out signals. Must be processed before any data collection begins on page load — not just a manual toggle.
gdpr-11-2-3M
Right to correct: confirm profile edit flows satisfy state law requirements (most states) Most US state privacy laws include a right to correct personal data (Utah is the notable outlier). Confirm existing profile-edit flows satisfy this requirement — same determination as GDPR rectification (gdpr-3-5).
gdpr-11-2-4S
Right to limit sensitive personal information (CCPA-specific — relevant if geolocation added) Relevant if DockBound ever collects precise geolocation, which cruise/port apps often do for "near me" features. Confirm current data collection and plan for if/when geolocation is added.
gdpr-11-2-5S
11.3 Consent & Notice Differences from GDPR 3 items
Build consent architecture supporting both opt-out (ordinary) and opt-in (sensitive) models per category Most US state laws are opt-out by default for ordinary data but require opt-in for sensitive data. Consent architecture must support both models per-category — not a single global toggle. Must interoperate with GDPR's opt-in-by-default posture.
gdpr-11-3-1L
CCPA-specific privacy policy disclosures (categories, sold/shared, retention, how to exercise rights) Privacy policy must include: categories of data collected, categories sold/shared (or a statement that none is), retention period per category, and how to exercise rights. Have counsel review before publishing.
gdpr-11-3-2M
"Notice at collection": just-in-time disclosure at point of data collection CCPA requires a just-in-time notice at the point data is collected — not just a buried policy link. Add contextual notices at sign-up, CSV upload, and any other data collection entry points.
gdpr-11-3-3M
11.4 Data Protection Assessments (State-Required) 1 item
Conduct state-required data protection assessments for CO, CT, VA, OR Colorado, Connecticut, Virginia, and Oregon require data protection assessments for higher-risk processing (profiling, sale of data, sensitive data processing). Can largely reuse the GDPR DPIA (gdpr-8-1) with state-specific formatting if requested by a regulator.
gdpr-11-4-1M
11.5 Enforcement & Cure Periods 3 items
Document cure period status per state; do not rely on post-complaint remediation for CA Cure periods are expiring or already gone in several states. California's CPRA-era violations have no cure period — "fix it after a complaint" is not a safe compliance strategy for CA.
gdpr-11-5-1S
Track California breach private right of action risk California is the only state with a private right of action for consumers, and only for data breaches (not general violations). Raises the bar specifically on breach prevention and the incident response plan (gdpr-7-1). Review security controls with this risk in mind.
gdpr-11-5-2S
Document state penalty caps for risk quantification Colorado: up to $20,000/violation, capped at $500,000. Most other states: $7,500–$10,000 per violation. Document these for risk quantification and prioritization decisions.
gdpr-11-5-3S
11.6 Sub-processor / Vendor Check (US Lens) 2 items
Confirm all vendors include CCPA "service provider"/"contractor" contract language Confirm Stripe, Firebase/Google Cloud, Travefy, Apify, and Twilio agreements include CCPA-required "service provider" or "contractor" contract language (distinct from GDPR's "processor" language, but functionally parallel). Many vendor DPAs cover both — confirm rather than assume.
gdpr-11-6-1S
Add contract carve-out if any vendor could "sell" data under CCPA's broad definition If any vendor could be deemed to "sell" data under CCPA's broad definition (which includes some data sharing, not just direct sales), add a specific contract carve-out restricting that activity.
