DPA Action Steps — Amy to Complete

Steps are self-serve via vendor dashboards unless otherwise noted. No engineering required.

1. Google Cloud / Firebase — Highest priority
  1. Sign in to Google Cloud Console at console.cloud.google.com with the DockBound project owner account.
  2. Navigate to IAM & Admin → Privacy & Security → Data Processing Agreement (or search "DPA" in the console search bar).
  3. Review and accept the Google Cloud Data Processing Agreement. This covers Firestore, Firebase Auth, and Cloud Functions under one DPA.
  4. Confirm the Firestore data location: in the Firebase Console → Firestore → Usage tab, note the region. If it is us-central1 (or any US region), Google's SCCs automatically cover EU/UK data subject transfers — no additional action needed.
  5. Document the confirmed region here: Firestore region: ___________

Google's DPA acceptance is account-level, not project-level. If the Google account already has a DPA accepted from another project, it covers DockBound too — verify acceptance date.

2. Stripe — High priority
  1. Log in to the Stripe Dashboard at dashboard.stripe.com.
  2. Navigate to Settings → Legal & Privacy → Data Processing Agreement.
  3. If no DPA is shown, go to stripe.com/legal/dpa — Stripe's standard DPA is available for acceptance online.
  4. Accept the DPA and note the acceptance date.
  5. While in Settings, confirm the Stripe Radar data retention setting — check that fraud/risk data retention aligns with your stated billing data retention (7 years for financial records).

Stripe's standard DPA includes SCCs for US→EU transfers. No separate SCC addendum is needed.

3. Twilio (covers both Twilio SMS and SendGrid)
  1. Log in to the Twilio Console at console.twilio.com.
  2. Navigate to Account → Legal → Data Protection Addendum.
  3. Accept the DPA. Twilio's DPA covers both the Twilio SMS platform and SendGrid (both are Twilio products).
  4. Confirm SMS log retention period in Twilio Console → Messaging → Logs — note the default retention period and align it with the Art. 30 records (R-07: 3 years for consent log; message content per Twilio DPA).

A single Twilio DPA acceptance covers both the SMS (Twilio Programmable Messaging) and email (SendGrid) products on the same account.

4. Travefy
  1. Contact Travefy via the partner/API channel (or your existing account representative).
  2. Request confirmation of their DPA terms for the API integration use case. Ask specifically: (a) do they have a standard DPA for API partners? (b) what personal data do they retain from API calls? (c) what are their data retention periods?
  3. Note: DockBound's Travefy integration does not send traveler personal data through the API — only port guide content. Confirm Travefy agrees with this characterisation.
  4. Document the outcome and file a copy of any DPA received.

If Travefy does not offer a formal DPA, document the inquiry and their response. For the limited personal data involved (advisor email as lookup key only), this is lower risk than the other vendors.

5. OpenAI
  1. Log in to the OpenAI Platform at platform.openai.com.
  2. Navigate to Settings → Privacy & Legal → Data Processing Agreement.
  3. Review and accept OpenAI's DPA for API usage.
  4. Confirm the zero-data-retention (ZDR) setting is enabled for the DockBound API key — this prevents OpenAI from training on submitted prompts. Navigate to Settings → API Keys → Data Controls.
  5. Verify (engineering): confirm that no personal data is included in port guide generation prompts. Port guide prompts should contain only port/location context — not names, emails, or traveler data.

Zero-data-retention is the recommended setting for any commercial API use. It may require a paid plan tier — confirm on the OpenAI platform.

After Completing DPA Steps

  1. Update the DPA Status column in the master table above (change ⏳ Pending to ✅ Done with acceptance date).
  2. File copies of all DPA acceptances in a secure location (e.g., a shared Google Drive folder accessible to the program DRI and legal counsel).
  3. Mark checklist items gdpr-4-1 through gdpr-4-5 as complete in docs/gdpr-compliance-checklist.html.
  4. Add the sub-processor list URL to the privacy policy when published (gdpr-4-6 / gdpr-10-4).
