1. How to Read This Document

This is the single source of truth for DockBound product work — completed, in progress, and planned. It replaces the individual phase plan files in memory. Architecture reference docs (what DockBound owns vs. PlatformCore, the *Bound pattern, API design) are kept separately in memory as they are design constraints, not work items.

Status key

Done Shipped and working
In Progress Actively being coded this sprint
Next Ready to start — no blockers, requirements clear
Backlog Planned but not yet sequenced
Blocked Cannot start — external dependency
Decision Needs a call before work can be scoped
Hold Intentionally deferred — revisit later

Size guide

XS <2 hours
S ~half day
M 1–2 days
L 3–5 days
XL 1–2 weeks
Epic Multi-week / significant architecture

Sizes assume 1 developer with Claude. A session is typically 4–6 hours of productive output. Sprint = 2 weeks of sessions. The /pm agent checks this doc weekly and flags items whose status looks stale relative to recent commits.

StateGovTravelAdvisory — Cloud Run intermediary for State Dept. RSS Fine at current scale Fetch frequency increases, Cloud Run has operational issues, or Aureum01 repo access becomes a problem What it is: A standalone Express + TypeScript server (submodule at Aureum01/StateGovTravelAdvisory, deployed to Cloud Run) that proxies the U.S. State Department public RSS feed at travel.state.gov/…/traveladvisories.xml. It adds rate limiting, caching, and OpenAPI docs on top of the raw RSS.

How DockBound uses it: The alertsScheduledFetch Cloud Function (functions/index.js ~line 5796) runs on a cron at 6 AM + 6 PM ET (2×/day). It reads the TRAVEL_ALERTS_API_URL Firebase Secret, calls the Cloud Run service, and writes advisory data to Firestore. The dataSource field on each record is set to 'travel-advisory-api' (line ~6023) confirming this path.

Why it's fine now: Two fetches per day means essentially zero volume pressure. The rate limiting and caching the middleware provides are meaningless at this load. The Cloud Run service is not in DockBound's GitHub org — it lives under Aureum01/StateGovTravelAdvisory which the pandadammit-cloud account cannot push to (confirmed 2026-09-01).

The simpler alternative (when needed): alertsScheduledFetch could call https://travel.state.gov/content/travel/en/traveladvisories/traveladvisories.xml/ directly — it is a public RSS feed, no auth required. Remove the Cloud Run service entirely. The middleware's rate limiting and caching are irrelevant at 2×/day. This would eliminate the external Cloud Run dependency and the cross-org repo problem in a single PR.
